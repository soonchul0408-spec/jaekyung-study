# 재경관리사 기출 노트 사이트 구조 기준

이 문서는 새 시험 회차를 추가하거나 화면을 확장할 때 **현재 운영 중인 사이트 구성과 톤을 최우선 기준**으로 유지하기 위한 기준 문서다.

배포 전에는 반드시 [회차 추가 품질검사표](QUALITY_CHECKLIST.md)를 확인한다.

## 유지해야 할 사용자 흐름

1. 홈
   - `01 연도별 기출`: 먼저 월별 회차를 선택한 뒤 과목·번호로 문제를 빠르게 연다.
   - `02 항목별 복습`: 과목과 세부 주제로 문제를 찾는다.
   - `03 헷갈리는 문제`: 사용자가 저장한 문제를 다시 본다.
   - `04 빈출 분석`: 공개기출 분석 기준 TOP 12 유형을 확인하고 연결된 문제로 이동한다.
2. 문제 화면
   - 문제 지문과 선택지를 먼저 보여 준다.
   - `근거 보기`, `풀이 방향 보기`, `정답 및 해설 보기`는 필요할 때만 펼친다.
   - 빈출 배지와 헷갈림 저장 기능을 함께 보여 준다.
3. 긴 목록
   - 기본으로 모두 펼치지 않는다.
   - `문제 목록`, `선택한 주제의 문제`, `저장한 문제 목록`은 접힌 상태에서 사용자가 직접 펼친다.
   - 긴 내용을 열어도 현재 읽던 위치가 맨 위로 이동하지 않아야 한다.

## 화면·디자인 원칙

- 현재의 따뜻한 베이지 배경, 짙은 녹색 강조, 주황색 포인트, 둥근 카드와 버튼을 유지한다.
- 모바일 우선: 긴 탭·필터는 가로 스크롤을 허용하고, 배지·버튼은 줄바꿈돼도 읽을 수 있어야 한다.
- 상태는 색만으로 전달하지 않는다. 빈출 여부, 학습 완료 여부처럼 중요한 상태는 항상 텍스트를 함께 표시한다.
- 문제 텍스트는 한국어 단어 중간에서 강제 줄바꿈되지 않게 한다. PDF에서 추출한 줄바꿈은 데이터 생성 단계에서 정리하고, 표 형태 행만 줄바꿈을 보존한다.
- 새 기능은 전체 화면을 한 번에 길게 나열하기보다, 탭·필터·접기/펼치기 또는 문제 상세 화면으로 분리한다.

## 데이터 구조

### 문항 데이터

- 2025년 1월 문항 데이터는 `src/data/questions.js`, 3월 문항 데이터는 `src/data/questions-2025-03.js`에 있다. 화면에서는 두 파일을 합쳐 사용한다.
- 문항 ID 형식은 `YYYY-MM-{FR|TX|CM}-{01..40}`이다. 예: `2025-01-FR-21`.
- 신규 회차도 과목별 40문항, 총 120문항을 유지하고 기존 ID 규칙을 따른다.
- `subjectId`, `primaryTopicId`, `secondaryTopicIds`, `reviewNeeded`, `answer`, 해설 관련 필드를 보존한다.
- 분류와 해설 규칙은 `docs/EXPLANATION_QUALITY_STANDARD.md`를 따른다.

### 분류 기준

- `src/data/taxonomy.json`의 topic ID를 우선 사용한다.
- 새 회차의 세부 논점이 기존 taxonomy에 정확히 없을 때만 해당 과목의 `OTHER` 토픽을 쓰고 `reviewNeeded: true`로 표시한다.
- 기존 문제의 ID·정답·분류를 단순한 화면 개선 때문에 변경하거나 삭제하지 않는다.

### 빈출 분석 기준

- `src/data/frequencyAnalysis.js`가 빈출 분석의 단일 기준 데이터다.
- 각 항목은 다음 필드를 유지한다.

```js
{
  subject: 'FR',
  rank: 1,
  topicName: 'K-IFRS·개념체계·표시',
  problemIds: ['2025-01-FR-01'],
  questionCount: 11,
  note: '분석 기준 설명',
}
```

- `questionCount`는 공개기출 8회분 분석 기준 수치다.
- `problemIds`에는 **현재 사이트에 실제 존재하는 문항만** 넣는다. 없는 문항을 임의로 만들지 않는다.
- 문제는 하나의 빈출 항목에만 연결한다. 중복 ID, 존재하지 않는 ID, 과목 불일치는 `npm run check:frequency`에서 실패해야 한다.
- 새 회차를 추가하면 해당 회차의 실제 문항 ID를 기존 TOP 12 항목에 추가한다. 근거가 부족하면 `problemIds`를 비워 두고 `note`에 현재 회차 미연결 사실을 적는다.

## 저장 상태

`localStorage` 키 `jaekyung-study-state`에는 다음 상태가 유지된다.

- `currentId`: 마지막으로 연 문제
- `favorites`: 헷갈리는 문제 ID 목록
- `studiedFrequencyKeys`: 빈출 유형 학습 완료 상태 (`FR-1` 같은 과목-순위 키)

새 상태를 추가할 때는 기존 필드를 보존하고 `persist()`를 통해 함께 저장한다.

## 신규 회차 추가 순서

1. 문제지·확정답안 원문을 준비한다.
2. `scripts/buildExamData.mjs` 또는 신규 회차용 생성 절차로 문항 데이터를 만든다. 3월은 `npm run generate:march-data`를 사용한다.
3. 120문항, 과목별 40문항, ID 형식, taxonomy 분류를 확인한다.
4. `docs/EXPLANATION_QUALITY_STANDARD.md`에 따라 해설과 계산 검증 정보를 채운다.
5. 실제 문항에 근거해 `frequencyAnalysis.js`의 `problemIds`만 추가·수정한다.
6. 아래 검증을 통과한 후 배포한다.

```bash
npm run check:frequency
npm run check:exam-parity
npm run check:exam-quality
npm run check:explanations
npm run build
```

`check:exam-parity`는 새 회차에 120문항·과목별 40문항, 확정답안, 지문·보기 근거, 풀이 방향, 해설, 1월 이상 수준의 검증 계산 과정, 과목별 TOP 12 연결이 모두 있는지 확인한다. 하나라도 빠지면 배포하지 않는다.

`check:exam-quality`는 새 회차가 공통 템플릿 문구만 반복하지 않는지, 모든 답안 설명에 실제 정답 선택지 표현이 포함되는지, 풀이 방향의 찾을 표현이 지문과 연결되는지, 보기별 설명이 충분한지, **계산형 모든 문항에 계산식·수치 대입·결과·확정답안 대조가 있는지**, 그리고 **‘옳지 않은 것’ 문항의 정답 선택지에 실제 표현을 인용한 오답 이유가 있는지**를 검사한다. 이 검사가 실패하면 배포하지 않는다.

`check:explanations`에서 기존 미작성 계산형 문항이 있으면, 그 실패를 새 회차 데이터와 구분해 해결한다.
